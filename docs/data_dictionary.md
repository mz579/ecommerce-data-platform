# 数据字典（Phase 1）

> 本文档所有统计数字均来自 `src/ecommerce_dw/eda` 对原始 CSV 的**实际全量扫描**
> （`notebooks/01_eda.ipynb`，无数据库、只读本地文件），非估算。
> 数据为 Retailrocket recommender system dataset，许可 CC BY-NC-SA 4.0，来源见 `docs/dataset.md`。
>
> 原始文件为 time-series/日志型 CSV，所有时间戳为 **Unix 毫秒**（整数），本文统一按 **UTC** 解读。

## 1. events 行为事件表

文件：`data/raw/retailrocket/events.csv`，2,756,101 行，5 列，表头
`timestamp,visitorid,event,itemid,transactionid`，无畸形行。

| 字段 | 推断类型 | 含义 | 可空 | 实际取值域 | 跨列覆盖率 | 来源 / 注意 |
| --- | --- | --- | --- | --- | --- | --- |
| `timestamp` | int | 事件发生时刻，Unix 毫秒 | 否 | `1430622004384`（2015-05-03 03:00:04 UTC）~ `1442545187788`（2015-09-18 02:59:47 UTC），覆盖 139 个 UTC 日 | 2,756,101 / 2,756,101 = 100% | 解析无异常（0 个非法 / 负数时间戳）。2,750,455 个不重复毫秒值；2,756,101 − 2,750,455 = **5,646** 行冗余，实际与他人共享同一毫秒的行数为 **10,795**（分布在 5,149 个共享毫秒值上）。**文件内按时间不单调**：以线性顺序逐行比较，1,377,377 行的 ts 小于前一行，行序接近随机；也不是按 visitor 分组（相邻行同 visitor 仅 7,406 处）。 |
| `visitorid` | int | 匿名访客 ID（Cookie 级匿名标识，非注册用户 ID） | 否 | 1,407,580 个不同值（任意行为口径；其中做过 `view` 的去重 1,404,178，即项目 UV 口径） | 100% 非空 | 有 **3 行取值为 `0`**，疑为未初始化/缺失哨兵值，ODS 阶段需单独标注。同一 visitor 跨天可复用，但匿名标识不应外推为真实用户。 |
| `event` | str | 事件类型 | 否 | 恰好 3 个取值：`view` 2,664,312（96.67%）、`addtocart` 69,332（2.52%）、`transaction` 22,457（0.81%） | 100% 非空 | 未发现集合外类型。`transaction` 即成交。 |
| `itemid` | int | 被浏览/加购/成交的商品 ID | 否 | 235,061 个不同值；无 `0` | 100% 非空 | 与 `item_properties.itemid` **不一一对应**：事件引用的商品 78.81%（185,246 / 235,061）在属性表中有记录，21.19%（49,815）完全无属性行；属性表共 417,053 个商品 ID，覆盖面大于被浏览集合。 |
| `transactionid` | str(int) | 成交（订单/购物车）标识 | 是（仅交易事件非空） | 非空行：22,457（与 `event=transaction` 行数完全一致）；去重后 **17,672** 个不同值 | 交易事件 22,457/22,457 均非空；view/addtocart 全部为空 | `transactionid` 是**订单级**标识而非行级：17,672 个不同值对应 22,457 条 transaction 事件，其中 **2,710 个 transactionid 出现在多行**（最多一笔含 31 行交易事件，`7063`）。语义需确认（多商品一单 vs 重复回执）——后续 DWD 去重口径必须决策。 |

## 2. item_properties 商品属性表（时间变化快照）

文件：`data/raw/retailrocket/item_properties_part1.csv`（10,999,999 行）+ `item_properties_part2.csv`
（9,275,903 行），表头相同：`timestamp,itemid,property,value`，合计 **20,275,902** 行。两 parts 可直接拼接，无重复行。

| 字段 | 推断类型 | 含义 | 可空 | 实际取值域 | 来源 / 注意 |
| --- | --- | --- | --- | --- | --- |
| `timestamp` | int | 属性快照时间，Unix 毫秒 | 否（4 列均 0 缺失） | `1431226800000`（2015-05-10 03:00:00 UTC）~ `1442113200000`（2015-09-13 03:00:00 UTC） | 观察到的取值恒为 **03:00:00 UTC** 这个小时刻度（拿 min/max 与抽样行核对），推断是按日定时全量快照；属性窗口（05-10 起）晚于 events（05-03 起），属性先于事件的说明不完全成立。 |
| `itemid` | int | 商品 ID | 否 | 417,053 个不同值 | 同一商品在时间轴上有多条属性记录（变化数据），**不是** SCD-1 的静态表。 |
| `property` | str | 属性名 | 否 | **1,104** 个不同属性名 | **属性名高度非结构化**：绝大多数是数字编码（如 `888`、`790`），仅 `available`（1,503,639 行）、`categoryid`（788,214 行）可读。Top 值：`888` 3,000,398、`790` 1,790,516、`available` 1,503,639、`categoryid` 788,214、`6` 631,471。后续建模需决定展开哪些属性、其余如何兜底。 |
| `value` | str | 属性值 | 否 | 1,966,868 个不同值（多为 1~15 字节短串） | 无统一类型：`categoryid` 的值是类目 ID 字符串（1,242 个不同值，其中 1,212 个在 `category_tree.categoryid` 中存在，**30 个越界**，如 `1046`、`1123`）；`available` 应为布尔串；`888` 等为编码串。 |
| （整行） | — | — | — | 完全重复行：0 行 | 行级去重后无重复，可据此判断该表为天然事实数据。 |

关联事实：`category_tree` 的 1,669 个类目中 457 个从未被任何 `categoryid` 属性引用；说明类目树比商品实际使用的类目大。

## 3. category_tree 类目树表

文件：`data/raw/retailrocket/category_tree.csv`，1,669 行，表头 `categoryid,parentid`。
完整读取（小文件），无重复节点定义。

| 节点数 | 根节点数 | 边数 | 最大深度 | 孤儿引用 | 环 |
| --- | --- | --- | --- | --- | --- |
| 1,669 | 25（`parentid` 为空） | 1,644 | 5（从根到最深子节点 5 跳） | **0**（所有非空 `parentid` 都能在 `categoryid` 中找到） | 0（无成环） |

结构完全是一棵良构多叉森林：25 棵根树、每节点至多一个父节点、无悬挂边。

## 4. 跨表引用关系与判定结论

| 关系 | 结论 |
| --- | --- |
| `events.itemid` → `item_properties.itemid` | 不完全外键：235,061 个事件商品中 185,246 个（78.81%）有属性，49,815 个（21.19%）无 |
| `item_properties["categoryid"].value` → `category_tree.categoryid` | 1,242 个值中 1,212 个（97.6%）命中，30 个越界（2.4%），属脏数据 |
| `category_tree.categoryid` ← `categoryid` 属性 | 森林 1,669 个类目仅 1,212 个被引用过 |

## 5. 数据质量小结（供 ODS/DWD 决策）

1. `events` 时间戳无缺失、无非法值，但**文件乱序**（不按时间升序、也不按 visitor 分组），增量处理必须以 `timestamp` 为准而不能依赖文件位置。
2. `visitorid=0` 共 3 行，需在契约中定义处置（保留 + 标注，不静默丢弃）。
3. `transactionid` 为订单级标识且可复用（2,710 个 ID 跨多行，单 ID 最多 31 行），成交件数 ≠ transaction 行数 ≠ 订单数，口径必须统一。
4. `item_properties.property` 是 1,104 种属性的自由文本字典，绝大多数为数字编码，无官方语义文档。
5. `categoryid` 属性值与 `category_tree` 存在 30 个不一致值；`item_properties` 无主键（同 `(itemid, property)` 可随快照时间重复），重复行 = 0，但 `(itemid, property, timestamp)` 仍非全序唯一（同一快照时刻可多条）。
6. 全量唯一组合键判断：两张表均不以 CSV 原始外键约束相互引用，后续建模需自建维度。

## 6. 时区约定

- 数据集无显式时区信息；`events` 以 UTC 解读得到 05-03 ~ 09-18 窗口（与公开资料一致）。
- `item_properties` 快照刻度固定在 03:00:00 UTC。
- 所有后续指标、分区键一律按 **UTC** 计算并显式标注，避免夏令时/本地时区歧义。
